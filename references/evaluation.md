# 评测与归因

## 选择能支持本轮结论的评测

| 层次 | 观察对象 | 不支持的推论 |
| --- | --- | --- |
| 辅助代码 | 真实执行、结果、输入不被意外修改等不变量 | 脚本通过不等于 Agent 正确使用 |
| 目标 Skill | Agent 使用候选完成业务任务的产物与行为 | 显式加载通过不证明自动触发可靠 |
| 开发元 Skill | 开发任务中的方法选择、能力分配、归因、交付，以及产出 Skill 的表现 | 单个产物合格不证明优于其他开发方法 |

围绕关键判据设计正常、缺失/冲突和会改变行动的边界案例，数量随风险决定。文字任务看事实支持、未知处理、行动可执行性等语义；不要只检测标题或固定词。需要专业真值时用可靠资料或领域审阅，不能让同一个模型的自信充当真值。

高风险任务在正式选择前还要校准 grader，并验证真实专业案例套件；语义近重复、跨留出泄漏和标签冲突由数据集审计处理。具体命令与门禁见 [生产保证、恢复与治理](production-assurance.md)。构造案例通过只能证明工作流，不能替代真实 HFSS 等专业质量证据。

已有标注案例或需要自动多轮改进时，改用 [标注案例自动优化](labeled-case-optimization.md) 的隔离、分组和晋升门禁，并按 [标注与结果格式](eval-schema.md) 保存输入与结果。自动化不能降低真值要求。

## 执行设计

在候选执行前保存目标、判据、输入、已审批设计与保证产物标识（适用时）、候选内容标识和可用环境。代码用公开入口实际运行，检查返回值、产物和有意义的副作用；文本 Skill 让 Agent 实际完成用户任务。构造数据可以支持真实执行，但不能称为真实业务验证。

若使用独立 Agent，提供候选、自然任务和最少原始资料；不提供预期答案、作者诊断、拟议修复或其他组的输出。只在允许委派且能提供新上下文时执行；否则记录自查及限制。共享文件系统中的目录约束属于指令隔离，不等于系统强制隔离。保留原始产物与可观察执行记录，不索取内部推理。

触发评测用未显式指定 Skill 的请求与实际加载证据；显式调用单列为执行评测。没有加载观测能力时把自动触发记为未验证，不能用描述文字检查充数。

比较收益时给各组相同需求、资料、工具权限和可比较预算，保持评分一致。基线可以是普通 Agent、旧 Skill、现有 skill-creator 或其他可用方法；连续迭代使用当前最佳候选作为下一轮基线。允许基线同样成功，不为制造差异而削弱基线。主观产物需要时随机隐藏版本身份做盲比较。配置成本门禁但没有可靠用量或耗时数据时结论应为不可判定，不能把缺失值当作零。

## 记录与修正

每次运行记录：层次、设计标识（适用时）、候选标识、案例集标识、输入、环境及限制、实际输出位置、结果状态、评分依据。状态区分通过、失败、未执行、环境阻断、不可判定和案例无效。分别计数，环境阻断、不可判定和案例无效不按失败悄悄混入通过率；重复运行和重叠案例不累加为独立样本。

发现问题时先保存原始失败产物；重跑输出放新位置，防止覆盖唯一的失败证据。按下面信息关闭问题：

- 观察到什么，哪个输入/输出证明它，影响哪个完成标准。
- 失败层的证据，以及为什么本次修改能解决它；不能定位时补一个能区分原因的检查。
- 修改的范围、同类缺陷检查、避免过度修正的相反案例。
- 修正后实际证据与仍未知的范围。

修改方法返回方法设计；工具或能力问题修对应实现；指令问题改入口或参考；评分错误修后重评所有比较组。不要同时改多个层面掩盖原因，也不要为失败样例堆积专用口令。

看过并用于修正的留出案例转为回归。若仍要宣称泛化，另取未见案例；不需要该声明时，报告回归即可。最终内容变化后说明哪些证据仍适用、哪些需重验；不能把旧版本 Agent 运行悄悄标成新版本验证。

验证足以回答本轮问题后停止。单次跨领域执行可以证明流程可执行，不能证明普遍增益或生产可靠性。
